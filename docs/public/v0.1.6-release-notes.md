# Agent Data Hub v0.1.6

Agent Data Hub v0.1.6 is a small maintenance and first-run hardening release
for the local-first technical preview.

It does not add a new memory model or a new agent workflow. The release makes
the existing public demo path safer, faster to rerun, and easier to maintain.

## What Changed

### Safer LAN Read Behavior

- Hub View still binds to `127.0.0.1` by default.
- Binding Hub View to a non-loopback host now requires the explicit
  `--allow-lan-read` flag.
- The public mobile preview path uses that explicit opt-in and explains that it
  is read-only local-network exposure for trusted Wi-Fi, not hosting.
- Review Inbox and Codex setup writes stay disabled when Hub View is not bound
  to loopback.

### Hub View Structure

- Hub View templates are split into focused view partials:
  - project detail
  - agent context handoff
  - review inbox
  - shared copy actions
- Hub View Python code is split by responsibility:
  - `hub_view.py` stays the public compatibility entrypoint
  - `hub_view_models.py` owns data loading, view models, context handoff data,
    and rendering
  - `hub_view_server.py` owns WSGI routing, local POST actions, the LAN-read
    guard, and server startup
- The split is behavior-preserving. Routes, copy, POST boundaries, and public
  smoke expectations stay the same.

### Faster Project Overview Loading

- Hub View project cards now batch their memory counts and latest-report lookups
  across projects.
- The overview no longer builds a compiled-memory payload for every project
  card.
- The selected project detail still loads the full reviewed-memory view for the
  active project.

### First-Run Reuse

- `scripts/first_run_demo.sh` still creates `.venv` when needed.
- It now reuses the existing local install when the ADH package, core
  dependencies, and `pyproject.toml` fingerprint still match.
- If the install is missing or stale, it runs `pip install -e` again and updates
  the local install stamp.
- Existing `.env` files are still preserved.

### Release Hygiene

- `pyproject.toml` now matches the next public patch version.
- The release checklist explicitly keeps package version and tag aligned.
- The first-run protocol is kept on the current `main` line rather than a stale
  historical tag.

## Recommended First Run

From a fresh folder:

```bash
git clone https://github.com/AlexanderSmyslowski/central-agent-data-hub.git
cd central-agent-data-hub
scripts/first_run_demo.sh
```

For a non-blocking check without starting Hub View:

```bash
scripts/first_run_demo.sh --no-hub-view
```

For a phone preview on the same trusted Wi-Fi:

```bash
scripts/first_run_demo.sh --mobile
```

## Verification

The release candidate was checked with:

```bash
git diff --check
bash -n scripts/*.sh
.venv/bin/python -m compileall agent_hub
.venv/bin/python -m pytest -q
scripts/smoke_public_demo.sh
scripts/first_run_demo.sh --no-hub-view
.venv/bin/python -m agent_hub.cli status
.venv/bin/python -m agent_hub.cli check
```

The first-run script was also run twice locally to verify that the second run
reuses the existing install instead of reinstalling unnecessarily.

## Boundaries

- no schema change
- no migration
- no new dependency
- no new Hub-memory write path
- no autonomous agent execution
- no hosted service
- no MCP write tools
- no authentication or role system

## Release Position

v0.1.6 is suitable for evaluating Agent Data Hub as a small local technical
preview with a smoother public first run and a more maintainable Hub View code
base.

It remains a technical preview. This release improves safety, speed, and
maintainability; it does not turn ADH into a hosted app or change the reviewed
memory model.
