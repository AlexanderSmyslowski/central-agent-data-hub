# v0.6 Definition

Agent Data Hub v0.6 should prove a CLI-first real-project bootstrap.

The goal is not to become a standalone hosted product. The goal is to make the
first real-project step feel like part of the installed tool, not like a
maintainer-only shell convention.

## v0.6 Bootstrap Loop

The v0.6 loop starts after the public demo and checkout install:

1. Install the checkout with `pip install -e .`.
2. Register a local Git repository with `agent-hub register-project`.
3. Install the repo-local `AGENTS.md` block as part of the same command.
4. Start work from that repository with reviewed context.
5. Review one draft explicitly.
6. Confirm that `prepare`, `handoff`, and `agent_finish` see the reviewed item.

## What Must Be Proven

The external-developer smoke must use:

```bash
agent-hub register-project
```

or the equivalent module invocation through the local checkout. The older
`scripts/register_project.sh` remains a compatibility path for operators and
repo-local automation, but it is not the primary public bootstrap story.

## What Stays Out

v0.6 still does not mean:

- non-checkout package installation as the main path
- hosted deployment
- production authentication or roles
- automatic memory capture
- automatic draft promotion
- replacing the start/finish shell wrappers

## Acceptance Bar

ADH reaches this v0.6 bar when the CLI registration command is tested, public
docs recommend it for daily first-project bootstrap, and the
external-developer smoke proves the CLI path locally and in CI.
