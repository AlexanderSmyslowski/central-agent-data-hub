# Agent Data Hub v0.1.4

Agent Data Hub v0.1.4 is a small visibility hardening release for the
local-first technical preview.

It makes one thing explicit that was previously implicit: when reviewed
project memory is handed to a chatbot or local agent, that handoff is now
visible and honest. It does not change the memory schema, add a hosted
service, add a write path, or run any agent automatically.

## What Changed

### Visible Agent Context In Hub View

- The project page now has a **Connect an agent** section.
- One click on **Create context pack** produces a visible ADH context handoff
  for the selected project and task.
- The result view shows which reviewed memory was loaded: facts, decisions,
  risks, open questions, reports, context-trail entries, and known gaps, plus
  how that context should influence the agent.
- The context pack is copy-paste ready for chatbots and shows copy buttons for
  the local-agent setup commands, config shape, startup instruction, terminal
  fallback, and chatbot context pack.
- The whole path reuses the existing read-only `prepare` surface. It does not
  create a second source of truth and adds no write path.

### Clearer Local Agent Connection

- Hub View now separates chatbot use, local agent connection, and terminal
  fallback.
- Chatbots still use copy/paste because they cannot automatically read local
  ADH context.
- Local agents are framed as a one-time connection path through MCP or an
  equivalent startup rule; after setup, the local agent is instructed to request
  ADH context at the start of ADH-related work.
- Hub View shows the setup steps and provides copy buttons, but it does not
  write the local agent's configuration by itself.
- `scripts/agent_start.sh` remains visible as a manual fallback until the local
  agent is connected. It is not automation and it is not the intended long-term
  daily UX.
- Hub View shows the context handoff and counts, but does not claim that an
  unconnected agent has read or used the context.

### Visible Context Receipt At Agent Start

- `scripts/agent_start.sh` now prints an `ADH Context Loaded` receipt before the
  compiled project memory, with the loaded counts and how the context should
  influence the work.
- `agent-hub prepare` includes the same receipt block at the top of its
  Markdown output, so the chatbot copy-paste path is equally explicit.
- Hub View, `prepare`, and the agent-start receipt share one source for the
  influence wording, so the three surfaces cannot drift apart.

### Honest Framing

- Every surface states that context is being **handed to** an agent, not that
  an agent has already used it.
- Counts reflect what each surface actually loads: the agent-start receipt
  counts the compiled memory it prints, and the `prepare` receipt counts the
  prepared pack.

## Recommended First Run

From a fresh folder:

```bash
git clone https://github.com/AlexanderSmyslowski/central-agent-data-hub.git
cd central-agent-data-hub
scripts/first_run_demo.sh
```

Then, on a project page in Hub View, use **Connect an agent -> Create context
pack** to see the visible handoff.

For chatbots, copy the context pack into the chat. For local agents, use the
copy buttons for the MCP or startup-rule setup shown in Hub View. After setup,
the local agent is instructed to request reviewed context at task start. Hub
View does not write the agent configuration by itself.

If the local agent is not connected yet, use the manual terminal fallback:

```bash
scripts/agent_start.sh --project <project-slug> --query "<task>" --review
```

## Boundaries

- no schema change
- no migration
- no new dependency
- no write path from the new surfaces
- no autonomous agent execution
- no hosted service
- no MCP write tools
- no authentication or role system

## Release Position

v0.1.4 is suitable for evaluating Agent Data Hub when the question is not only
"what reviewed memory exists?" but "can I see that my agent is actually being
handed that reviewed memory, and how it is meant to shape the work?"

It remains a technical preview. The release improves visibility and honesty of
the agent handoff. It does not turn Hub View into a hosted product or change the
underlying reviewed-memory model.
