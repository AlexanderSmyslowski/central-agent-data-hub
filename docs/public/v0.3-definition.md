# v0.3 Definition

Agent Data Hub v0.3 should prove the local multi-agent trust loop.

The goal is not to run every agent or collect every message. The goal is to
make the path from unreviewed candidate to reviewed context visible,
auditable, and reusable by different local agents.

## v0.3 Trust Loop

The v0.3 loop is:

1. A useful Signal Inbox note or agent observation becomes a memory candidate.
2. Deterministic routing stores ordinary candidates as `draft` and sends risky
   candidates to explicit review.
3. A responsible reviewer can see the draft in the Review Inbox.
4. A human accepts or rejects exactly one draft at a time through a reviewed
   channel.
5. The audit trail records who reviewed it, which channel submitted the review,
   and who was responsible.
6. Accepted memory appears in task-specific `prepare` output as reviewed
   context.
7. The next handoff, prepare pack, or read-only MCP surface can show the
   reviewed residue to another agent or session.

## What Must Be Proven

v0.3 requires an executable trust-loop smoke:

```bash
scripts/smoke_trust_loop.sh
```

The smoke runs against an isolated demo database. It creates a temporary
Signal Inbox-style note, turns it into draft candidates, verifies that
`prepare` labels an unreviewed draft as unconfirmed, accepts one draft through
the CLI Review Inbox, accepts a second draft through the public Review API with
`review_source=telegram`, verifies the audit metadata, then confirms that
`prepare`, `handoff`, and the read-only MCP prepare payload see the accepted
facts as reviewed memory.

CI must run this smoke as its own job, separate from unit tests, fresh-clone
demo, and upgrade drill.

## What Stays Out

v0.3 still does not mean:

- automatic memory capture from chats
- automatic draft promotion
- write-capable MCP tools
- chat adapter code inside this repository
- production authentication or roles
- hosted service behavior
- vector search or embeddings

## Acceptance Bar

ADH reaches this v0.3 bar when the trust-loop smoke is green locally and in CI,
and the public docs clearly state that reviewed memory only appears after an
explicit review action.
