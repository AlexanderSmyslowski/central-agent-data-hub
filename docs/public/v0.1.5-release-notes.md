# Agent Data Hub v0.1.5

Agent Data Hub v0.1.5 is a small local-agent setup hardening release for the
local-first technical preview.

It continues the visibility work from v0.1.4. The main change is practical:
Hub View can now help connect Codex without asking a first-run user to know or
replace a project folder path by hand. It still does not run an agent, does not
write Hub memory, and does not add a hosted service.

## What Changed

### Clearer Agent Cards In Hub View

- Hub View now separates the local-agent paths more explicitly:
  - Claude Code
  - Codex
  - Hermes or custom agent
  - other MCP-compatible agents
  - terminal fallback
- The terminal path is framed as a fallback, not the normal daily workflow.
- The visible copy still says that ADH can show the handoff and setup material,
  but cannot prove that an unconnected agent used the context.

### Guarded Codex Setup From Hub View

- When ADH knows a project's local folder from project metadata, Hub View shows:
  - the project folder
  - the target `AGENTS.md` file
  - the planned action
  - a preview of the ADH block before writing
- The user can then install the Codex setup block with an explicit local click.
- The existing copyable terminal command remains available as a fallback.
- The setup action writes only the repo-local `AGENTS.md` working-rule file.
  It does not write reviewed Hub memory and does not run Codex.

### Safer Public Demo Behavior

- The public demo can show the current checkout path for orientation.
- It intentionally does not install a demo-project block into the repository's
  own `AGENTS.md`.
- In the public demo, the Codex card shows a preview and a dry-run fallback
  command instead of an enabled install action.

### Local Mobile Preview

- `scripts/first_run_demo.sh --mobile` starts Hub View on the local network and
  prints a phone URL when the machine's LAN address can be detected.
- This is a local preview mode for a trusted Wi-Fi network, not hosting.
- Review Inbox and Codex setup writes stay disabled because Hub View is not
  bound to loopback in this mode.

### Shared Repo-Agent-Memory Logic

- The repo-local `AGENTS.md` block planning and installation logic now lives in
  `agent_hub.repo_agent_memory`.
- `scripts/install_repo_agent_memory.sh` reuses the same logic as Hub View.
- Tests cover preview, create, update, unchanged, path guardrails, Hub View
  POST/CSRF behavior, and the public-demo dry-run boundary.

## Recommended First Run

From a fresh folder:

```bash
git clone https://github.com/AlexanderSmyslowski/central-agent-data-hub.git
cd central-agent-data-hub
scripts/first_run_demo.sh
```

For a phone preview on the same trusted Wi-Fi:

```bash
scripts/first_run_demo.sh --mobile
```

Then open Hub View, choose a project, and use **Connect an agent -> Create
context pack**.

For chatbots, copy the context pack into the chat.

For Codex:

- if ADH knows the real project folder, review the `AGENTS.md` preview and use
  **Install Codex setup**
- in the public demo, treat the Codex card as a preview and dry-run example

## Boundaries

- no schema change
- no migration
- no new dependency
- no Hub-memory write path
- no autonomous agent execution
- no shell command execution from Hub View
- no hosted service
- no mobile write path
- no MCP write tools
- no authentication or role system

The only new write action is a guarded local file write to a repo's
`AGENTS.md`, after an explicit click, when ADH already knows the project folder.

## Release Position

v0.1.5 is suitable for evaluating the first real connection step between
reviewed ADH context and Codex.

It remains a technical preview. The release improves the local setup path and
makes the Codex handoff more concrete, but it does not turn ADH into a hosted
agent platform or claim that agents magically use context without being
connected.
