# Agent Data Hub v0.1.2

Agent Data Hub v0.1.2 is a small hardening release for the local-first
technical preview.

It collects the review-safety, draft-visibility, read-only integration,
versioned context-pack, and OKF export improvements that landed after v0.1.1.
It is still not a hosted product, broad automation platform, or finished
end-user application.

## What Changed

### Public First-Run Hardening

- The public demo database path now forces a separate demo database identity.
- The public demo path ignores `.env` `DATABASE_URL` for its own process and
  refuses non-demo database targets.
- The public getting-started guide documents the explicit public Hub View start
  mode.

### Draft Review And Attribution

- Draft memory candidates stay outside reviewed memory until explicitly
  accepted.
- Accept/reject actions require a reviewer handle.
- Review audit metadata records `reviewed_by` and `review_source`.
- Reviewer routing is attribution, not access control.
- Public templates leave reviewer identity unset so it is chosen explicitly.

### Agent-Facing Context Safety

- Agent-facing reads hide drafts and inactive memory by default.
- Daily human summaries still show pending draft counts.
- `agent-hub prepare` includes a Context Trail and Known Gaps section so agents
  can see why context was included and where reviewed memory may be thin.
- `prepare --format json` now has `context_pack_version: 1` as the first
  top-level field.

### Read-Only Integration Surfaces

- A read-only MCP server exposes reviewed context over stdio.
- The MCP surface can list projects, prepare context packs, search reviewed
  memory, and return project briefs.
- MCP has no write tools and cannot remember, import, accept, reject, sync, or
  modify memory.
- External review adapters get a small supported `agent_hub.review_api`
  facade; adapter implementations remain outside this repository.

### Portable Exports

- `agent-hub export-okf` writes a deterministic OKF-compatible preview bundle
  from reviewed memory.
- Drafts, proposed items, archived items, rejected decisions, resolved risks,
  and superseded reports are excluded from OKF export.
- OKF remains an export target, not an import path, sync engine, or second
  source of truth.

## Recommended First Run

Use the public getting-started guide:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
cp .env.example .env

scripts/db_start_public_demo.sh
scripts/smoke_public_demo.sh
AGENT_HUB_PUBLIC_DEMO=1 scripts/hub_view.sh
```

For details, see [`docs/public/getting-started.md`](getting-started.md).

## Boundaries

- no hosted service
- no autonomous promotion of unreviewed memory
- no OKF import or sync
- no MCP write tools
- no authentication or role system
- no Telegram or adapter implementation in this repository
- no destructive cleanup of existing OKF output directories

## Release Position

v0.1.2 is suitable for developers evaluating local reviewed memory, agent
context preparation, draft review, read-only agent integration, and portable
reviewed-memory export.

It remains a technical preview. The project still favors explicit review,
small local surfaces, and conservative automation boundaries over broad product
automation.
