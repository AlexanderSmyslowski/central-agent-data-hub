# v0.8 Definition

Agent Data Hub v0.8 should make local runtime health visible before agent work
or release checks depend on it.

The goal is not to add a supervisor, daemon, automatic repair, or hosted
monitoring. The goal is to make common local failures legible: low disk space,
an unusable temp directory, Docker or Compose trouble, wrong demo/operator
targets, occupied ports, missing backups, and migration drift.

## v0.8 Runtime Health Loop

The v0.8 loop is:

1. Run the doctor before changing local Docker state by hand.
2. See the selected target: operator database or public demo database.
3. See host runtime signals: free disk, temp directory, Docker, Compose, port,
   container, volume, Postgres readiness, logs, backup health, status, and
   check.
4. If the Hub is not ready, get one clear next action.
5. If the issue is only a warning, keep it visible without pretending the
   system is broken.
6. If the issue is unsafe for agent writeback, stop before reviewed memory is
   written.

## What Must Be Proven

v0.8 requires:

```bash
agent-hub doctor
scripts/db_doctor.sh --public-demo
scripts/agent_preflight.sh --compact
scripts/release_candidate_check.sh
```

The doctor and preflight output must mention host runtime health, including
disk and temp-dir checks. The release-candidate check must remain green after
the extra diagnostics.

## What Stays Out

v0.8 still does not mean:

- automatic recovery
- deleting containers or volumes
- changing Hub memory rows
- hosted monitoring
- background restarts
- auto-tagging a release

## Acceptance Bar

ADH reaches this v0.8 bar when local runtime problems are visible before they
break the agent loop, the recommended next step is specific, and diagnostics
remain read-only unless the human explicitly runs a separate recovery command.
