# v0.4 Definition

Agent Data Hub v0.4 should make the daily agent loop operationally reliable.

The goal is not to add a background supervisor or hosted runtime. The goal is
to make the local system honest when the Hub is ready, and equally honest when
the Hub is offline.

## v0.4 Reliability Loop

The v0.4 loop is:

1. `agent_start.sh` and `agent_finish.sh` run operational preflight before
   they rely on Hub context or reviewed writeback.
2. If the local Hub is ready, the run can load reviewed context, finish with a
   handoff, and optionally export or back up reviewed memory.
3. If the local Hub is offline, the scripts stop with an operational exit code
   and clear next actions.
4. A failed finish explicitly says that no reviewed memory, export, backup, or
   review-memory write happened.
5. The human or operator can run the doctor/start path and then retry the same
   finish command instead of guessing which piece failed.

## What Must Be Proven

v0.4 requires an executable offline-behavior smoke:

```bash
scripts/smoke_agent_offline.sh
```

The smoke runs without touching Hub data. It points the wrappers at a missing
test container, confirms that preflight reports the Hub as offline, and confirms
that `agent_finish.sh` prints an Offline Finish Protocol instead of implying
that reviewed memory was written.

CI must run this smoke as its own job, separate from unit tests, public-demo
smoke, upgrade drill, and the v0.3 trust-loop smoke.

## What Stays Out

v0.4 still does not mean:

- a background daemon
- automatic restart or recovery
- automatic writeback after reconnect
- hosted monitoring
- write-capable MCP tools
- chat transcript storage
- production incident management

## Acceptance Bar

ADH reaches this v0.4 bar when the offline-behavior smoke is green locally and
in CI, and the public docs make clear that offline finish attempts write no
reviewed Hub memory.
