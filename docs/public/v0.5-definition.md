# v0.5 Definition

Agent Data Hub v0.5 should prove the first external developer success path.

The goal is not to become a packaged SaaS product. The goal is to make sure a
developer who is not the maintainer can move from the public demo into one real
local project without private state, hidden assumptions, or maintainer-only
project names.

## v0.5 First Project Loop

The v0.5 loop is:

1. Start from a neutral local demo database.
2. Register a new local Git repository as its own Hub project.
3. Install the repo-local Agent Data Hub instructions into that project.
4. Start agent work from inside that repository and load reviewed context.
5. Create one unreviewed memory candidate and keep it as a draft.
6. Review the draft explicitly with reviewer attribution.
7. Confirm that `prepare` and `handoff` see the accepted item as reviewed
   project context.
8. Finish the run with an auditable handoff.

## What Must Be Proven

v0.5 requires an executable external-developer smoke:

```bash
scripts/smoke_external_developer.sh
```

The smoke runs against an isolated demo database and creates a temporary local
Git repository. It uses the same public path a developer would use:
`agent-hub register-project`, the installed `AGENTS.md` block,
`agent_start.sh`, Review Inbox, `prepare`, `handoff`, and `agent_finish.sh`.

CI must run this smoke as its own job, separate from unit tests, public-demo
smoke, upgrade drill, the v0.3 trust-loop smoke, and the v0.4 offline smoke.

## What Stays Out

v0.5 still does not mean:

- standalone package installation as the main path
- hosted deployment
- production authentication or roles
- automatic memory capture
- automatic draft promotion
- external chat adapter code inside this repository
- a polished multi-user product

## Acceptance Bar

ADH reaches this v0.5 bar when the external-developer smoke is green locally
and in CI, and the public docs make clear that a first real project loop starts
with explicit project registration, not maintainer-local state.
