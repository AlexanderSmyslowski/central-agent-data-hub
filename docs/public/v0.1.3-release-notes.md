# Agent Data Hub v0.1.3

Agent Data Hub v0.1.3 is a small first-run and Hub View hardening release for
the local-first technical preview.

It focuses on the first public demo path: getting a fresh clone running,
opening Hub View, and understanding the local reviewed-memory overview without
maintainer context. It does not change the memory schema, add a hosted service,
or turn Hub View into a full application.

## What Changed

### One-Command Public Demo

- A fresh clone can now run the public demo with one command:

  ```bash
  scripts/first_run_demo.sh
  ```

- The script creates `.venv` if needed, installs the local CLI, creates `.env`
  from `.env.example` if missing, starts the isolated public demo database,
  runs the public demo smoke check, then starts Hub View and prints the local
  URL to open.
- `scripts/first_run_demo.sh --no-hub-view` runs the same setup and checks
  without starting the blocking Hub View process.
- The public Getting Started path now treats `agent-hub setup` as optional
  local operator setup, not as part of the public demo.

### Cleaner Public Demo Data

- The public demo seed is kept small and neutral.
- Old smoke/operator traces are guarded against in the public demo database
  path.
- The demo path refuses to continue when it detects stale smoke/operator traces
  instead of silently deleting or rewriting user data.

### Hub View First-Run Legibility

- Hub View uses consistent English copy in the visible first-run surface.
- The active project state is clearer.
- The first project screen now names the main concepts directly: reviewed
  memory, risks and questions, latest status, quality, and Review Inbox.
- The Review Inbox empty state explains what happens when there is nothing to
  review.
- The Hub View title/brand links back to the project overview.

### Hub View Navigation

- Summary tiles are now real navigation instead of dead affordances:
  - Reviewed memory -> `#reviewed-memory`
  - Risks and questions -> `#risks-and-questions`
  - Latest status -> `#latest-status`
  - Quality -> `#quality`
  - Review Inbox -> `/inbox`
- Target sections have stable anchors.
- Reviewed memory is grouped as decisions, facts, and reports.
- Risks and open questions are grouped together.
- Latest status is a separate section based on existing project metadata and
  reports.

### Review Inbox Wording

- Hub View now uses "items to review" and "suggested memory changes" in the
  first-level UI.
- The internal `draft` model remains unchanged.
- The Review Inbox link is framed as global: it shows all items to review
  across projects, not only the currently selected project.

### First-Run Test Protocol

- A structured first-run test protocol documents how to observe a real public
  demo run without explaining the product during the session.
- The protocol tests the current `main` public surface, not the historical
  `v0.1.2` tag.

## Recommended First Run

From a fresh folder:

```bash
git clone https://github.com/AlexanderSmyslowski/central-agent-data-hub.git
cd central-agent-data-hub
scripts/first_run_demo.sh
```

For a non-blocking check:

```bash
scripts/first_run_demo.sh --no-hub-view
```

For details, see [`docs/public/getting-started.md`](getting-started.md).

## Boundaries

- no schema change
- no migration
- no hosted service
- no search or dashboard feature
- no project-filtered Review Inbox route
- no autonomous promotion of unreviewed memory
- no authentication or role system
- no change to the internal draft/review policy

## Release Position

v0.1.3 is suitable for a fresh public first-run evaluation of Agent Data Hub as
a local reviewed-memory technical preview.

The release improves the path from clone to demo and makes Hub View more useful
as a local overview of reviewed project memory. It remains a technical preview,
not a finished product or a hosted collaboration system.
